# 跨服务调用说明

本项目微服务间调用采用两套机制并存：**Dubbo RPC**（强依赖）+ **OpenFeign**（弱依赖/批量查询）。

---

## 一、两种机制的分工

| | Dubbo RPC | OpenFeign |
|---|---|---|
| 协议 | Triple（二进制，非 HTTP） | HTTP（走 `/internal/**` 路径） |
| 服务发现 | 接口全限定名注册到 Nacos | 服务名（`mhp-account`）注册到 Nacos |
| 适用场景 | 强业务依赖，失败则整个操作终止 | 批量展示查询，拼装 VO 用 |
| 使用方式 | `@DubboReference` 注入，像本地方法一样调用 | `@FeignClient` 注入，发起 HTTP 请求 |
| 是否经过 Gateway | 否（直连目标服务） | 否（直连目标服务，`/internal/**` 不对外暴露） |
| 是否需要 token | 否 | 否（`SaTokenConfig` 白名单放行 `/internal/**`） |

**选择依据：**
- 用 Dubbo：操作必须成功，失败没有降级空间（验证身份、校验预约状态、写回评分）
- 用 Feign：查展示信息，失败顶多展示不完整，批量场景居多

---

## 二、Dubbo RPC 调用

接口定义在 `mhp-common/src/main/java/com/mhp/booksystem/rpc/`，Provider 和 Consumer 共同依赖同一接口，编译期即可发现参数类型不匹配。

### RpcMerchantService（Provider：mhp-account）

```java
MerchantDTO getMerchantByUserId(Long userId);
void updateMerchantScore(Long merchantId, MerchantScoreUpdateDTO dto);
```

| Consumer | 调用方法 | 场景 |
|---|---|---|
| mhp-booking（ScheduleServiceImpl） | `getMerchantByUserId()` | 创建/修改档期前验证当前用户是商家身份 |
| mhp-booking（BookingServiceImpl） | `getMerchantByUserId()` | 创建/查看预约时验证商家身份 |
| mhp-booking（QuestionnaireServiceImpl） | `getMerchantByUserId()` | 创建/修改问卷前验证商家身份 |
| mhp-social（ReviewServiceImpl） | `getMerchantByUserId()` | 评价时验证被评价方是商家 |
| mhp-social（ReviewServiceImpl） | `updateMerchantScore()` | 评价成功后回写商家平均评分和评价数 |
| mhp-social（ComplaintServiceImpl） | `getMerchantByUserId()` | 投诉时验证投诉方是否为商家 |

### RpcBookingService（Provider：mhp-booking）

```java
BookingDTO getBookingById(Long bookingId);
```

| Consumer | 调用方法 | 场景 |
|---|---|---|
| mhp-social（ReviewServiceImpl） | `getBookingById()` | 评价前校验预约归属、状态必须为"已完成"（status=3） |
| mhp-social（ComplaintServiceImpl） | `getBookingById()` | 投诉前校验预约归属和状态 |

## 三、OpenFeign 调用

接口定义：`mhp-common/.../feign/AccountFeignClient.java`，对应 Provider `mhp-account` 的 `AccountInternalController`。

```
mhp-booking / mhp-social
  → @FeignClient(name = "mhp-account")
  → Nacos 负载均衡 → mhp-account:8081
  → AccountInternalController（/internal/**，无需 token）
```

### AccountFeignClient 接口一览

| 方法 | 路径 | Consumer | 场景 |
|---|---|---|---|
| `getUser(id)` | `GET /internal/user/{id}` | mhp-social（Message/Post） | 查单个用户昵称/头像 |
| `batchGetUsers(ids)` | `GET /internal/user/batch` | mhp-booking（Schedule/Booking）、mhp-social（Review/Message/Post） | 列表页批量拼装用户信息，避免 N+1 |
| `getMerchant(id)` | `GET /internal/merchant/{id}` | mhp-booking（Booking）、mhp-social（Complaint/Follow/Post） | 按 merchantId 查商家信息 |
| `getMerchantByUserId(userId)` | `GET /internal/merchant/by-user/{userId}` | mhp-social（Post） | 按 userId 查商家信息 |
| `batchGetMerchants(ids)` | `GET /internal/merchant/batch` | mhp-booking（Booking）、mhp-social（Follow/Post） | 列表页批量拼装商家信息 |

## 四、OpenFeign 调用流程

Feign 调用不走 Gateway，直接通过 Nacos 服务发现连到目标服务，目标 Controller 的 `SaTokenConfig` 已将 `/internal/**` 加入白名单，无需传 token。

```
调用方 Service
  → accountFeignClient.batchGetUsers(ids)   ← 本地接口调用
  → Feign 拦截器 → 组装 HTTP 请求
  → Nacos：lb://mhp-account → 选取实例（负载均衡）
  → HTTP GET mhp-account:8081/internal/user/batch?ids=1,2,3
  → AccountInternalController.batchGetUsers()
  → 返回 Result<List<UserDTO>>
  → Feign 反序列化 → 返回给调用方
```

## 五、调用方向总览

```
mhp-booking ──Dubbo──▶ mhp-account（验证商家身份）
mhp-booking ──Feign──▶ mhp-account（批量查用户/商家展示信息）

mhp-social  ──Dubbo──▶ mhp-account（验证商家身份、回写评分）
mhp-social  ──Dubbo──▶ mhp-booking（校验预约状态）
mhp-social  ──Feign──▶ mhp-account（批量查用户/商家展示信息）
```

调用方向单向无环，mhp-account 不调用其他服务，mhp-booking 不调用 mhp-social。

## 六、内部 HTTP 端点一览（AccountInternalController）

以下端点由 Feign 调用，不经过 Gateway，仅在微服务内网可达：

| 端点 | 用途 |
|---|---|
| `GET /internal/user/{id}` | 查单个用户 |
| `GET /internal/user/batch` | 批量查用户 |
| `GET /internal/merchant/{id}` | 按 id 查商家 |
| `GET /internal/merchant/by-user/{userId}` | 按 userId 查商家 |
| `GET /internal/merchant/batch` | 批量查商家 |
| `POST /internal/merchant/es/init` | ES 全量初始化（首次部署调用一次） |
| `GET /internal/booking/{id}` | 查单条预约（BookingInternalController，mhp-booking） |
| `GET /internal/ik/ext-words` | IK 扩展词库热更新（IkDictController，mhp-account） |
| `GET /internal/ik/stop-words` | IK 停止词库热更新（IkDictController，mhp-account） |
