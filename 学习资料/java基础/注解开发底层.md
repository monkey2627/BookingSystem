# Java 注解底层原理

---

## 一、注解是什么

注解（Annotation）是 **给代码元素（类、方法、字段、参数等）打的标签**，本身不直接改变程序行为，但可以被编译器、运行时框架或注解处理器读取并触发相应逻辑。

```java
// 一个注解的完整声明
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD, ElementType.TYPE})
public @interface MyAnnotation {
    String value() default "default";
    int priority() default 0;
}
```

`@interface` 是注解的声明关键字，和 `interface` 不同。

---

## 二、元注解（Meta-Annotation）

元注解是**用来修饰注解的注解**，控制被修饰注解的行为范围。

### @Retention — 注解的生命周期

| 值 | 说明 |
|----|------|
| `RetentionPolicy.SOURCE` | 只保留在源码，编译后丢弃（如 `@Override`、`@SuppressWarnings`） |
| `RetentionPolicy.CLASS` | 保留到 `.class` 文件，类加载时丢弃（默认值，字节码增强工具使用） |
| `RetentionPolicy.RUNTIME` | 保留到运行时，可通过反射读取（框架注解如 `@Component`、`@Autowired` 均使用此值） |

**框架用的注解几乎都是 `RUNTIME`**，否则反射读不到。

### @Target — 注解可作用的位置

```java
@Target({
    ElementType.TYPE,            // 类、接口、枚举
    ElementType.METHOD,          // 方法
    ElementType.FIELD,           // 字段
    ElementType.PARAMETER,       // 方法参数
    ElementType.CONSTRUCTOR,     // 构造器
    ElementType.LOCAL_VARIABLE,  // 局部变量
    ElementType.ANNOTATION_TYPE, // 注解（元注解就用这个）
    ElementType.PACKAGE,         // 包
})
```

不加 `@Target` 则可以用在任意位置。

### @Documented

加了此元注解的注解，会被 javadoc 工具提取到文档中。

### @Inherited

加了此元注解的注解，子类会**自动继承**父类上该注解（只对类级别的注解有效，方法上无效）。

```java
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Auditable { }

@Auditable
class Parent { }

class Child extends Parent { }   // Child 也被视为有 @Auditable
```

## 三、注解的底层实现

### 注解本质是接口

`@interface` 声明的注解，编译后会生成一个**继承自 `java.lang.annotation.Annotation` 的接口**。注解里声明的方法（如 `value()`、`priority()`）就是接口的抽象方法。

```java
// 编译后等价于：
interface MyAnnotation extends java.lang.annotation.Annotation {
    String value();
    int priority();
}
```

### 注解实例是动态代理对象

JVM 在运行时通过**动态代理**为注解接口生成实现类，`default` 值存储在代理对象中。当你调用 `annotation.value()` 时，实际上是在调用代理对象里查 `AnnotationInvocationHandler` 的 `memberValues` Map：

```
反射读取注解
  → 返回 $Proxy 对象（实现了 MyAnnotation 接口）
  → $Proxy 内有 AnnotationInvocationHandler
  → handler.memberValues = {"value": "xxx", "priority": 1}
  → annotation.value() 调用 → 从 Map 取出对应值返回
```

## 四、运行时读取注解（反射）

### 基本读取 API

```java
// 读取类上的注解
MyAnnotation ann = MyClass.class.getAnnotation(MyAnnotation.class);
if (ann != null) {
    System.out.println(ann.value());
}

// 读取方法上的注解
Method method = MyClass.class.getMethod("doSomething");
if (method.isAnnotationPresent(MyAnnotation.class)) {
    MyAnnotation ann2 = method.getAnnotation(MyAnnotation.class);
    System.out.println(ann2.priority());
}

// 读取字段上的注解
Field field = MyClass.class.getDeclaredField("name");
field.setAccessible(true);
MyAnnotation ann3 = field.getAnnotation(MyAnnotation.class);

// 读取方法参数上的注解（返回二维数组：每个参数对应一组注解）
Annotation[][] paramAnns = method.getParameterAnnotations();
```

### 注意：只有 RUNTIME 注解才能被反射读取

`SOURCE` 和 `CLASS` 级别的注解，运行时通过 `getAnnotation()` 只会得到 `null`。

## 五、注解处理器模式（框架内部实现方式）

框架注解（Spring 的 `@Component`、`@Autowired`、`@Transactional` 等）的工作原理都遵循同一套模式：

**定义注解 → 扫描类/方法/字段 → 反射读取注解 → 执行对应逻辑**

```java
// 模拟 Spring @Component 扫描逻辑（简化）
public void scanAndRegister(String packageName) {
    // 1. 扫描包下所有类（classpath 扫描）
    Set<Class<?>> classes = ClassScanner.scan(packageName);

    for (Class<?> clazz : classes) {
        // 2. 检查类上是否有目标注解
        if (clazz.isAnnotationPresent(Component.class)) {
            Component ann = clazz.getAnnotation(Component.class);
            String beanName = ann.value().isEmpty()
                ? toLowerCamel(clazz.getSimpleName())
                : ann.value();

            // 3. 执行对应逻辑：创建 Bean 并注册
            Object instance = clazz.getDeclaredConstructor().newInstance();
            beanContainer.put(beanName, instance);
        }
    }
}
```

### 字段注入注解示例

```java
// 模拟 @Autowired 字段注入
for (Field field : clazz.getDeclaredFields()) {
    if (field.isAnnotationPresent(Autowired.class)) {
        field.setAccessible(true);
        Object dep = beanContainer.get(field.getName());
        field.set(instance, dep);  // 注入依赖
    }
}
```

## 六、编译期注解处理器（APT）

`@Retention(RetentionPolicy.SOURCE)` 的注解在**编译期**由 APT（Annotation Processing Tool）处理，不需要运行时反射。

典型应用：
- **Lombok**：`@Data`、`@Getter`、`@Builder` 在编译期生成 getter/setter/builder 代码
- **MapStruct**：编译期生成类型映射实现类
- **Android ButterKnife**：编译期生成 bind 代码

APT 通过实现 `AbstractProcessor` 并注册到 `javax.annotation.processing.Processor` SPI 工作，编译器在编译时调用，生成新的 `.java` 文件一起编译。

## 七、常用内置注解

| 注解 | 用途 |
|------|------|
| `@Override` | 声明该方法是重写父类方法，编译器验证（SOURCE） |
| `@Deprecated` | 标记过时方法，使用时编译器警告（RUNTIME，可反射读） |
| `@SuppressWarnings` | 压制编译器特定警告（SOURCE） |
| `@FunctionalInterface` | 标记函数式接口，编译器验证只有一个抽象方法（SOURCE） |
| `@SafeVarargs` | 声明可变参数方法不会破坏类型安全（抑制泛型可变参数警告） |

## 八、关键概念速查

| 问题 | 答案 |
|------|------|
| 注解的本质是什么 | 继承 `Annotation` 接口的接口，运行时实例是动态代理对象 |
| 为什么框架注解都用 RUNTIME | 只有 RUNTIME 才能在运行时被反射读取 |
| `@Override` 为什么是 SOURCE | 只给编译器检查用，运行时不需要 |
| 注解能改变类的行为吗 | 不直接改变，需要框架/处理器扫描并执行对应逻辑才有效果 |
| Lombok 的 `@Data` 用的是哪种方式 | APT（编译期），SOURCE 级别，编译器在编译期生成代码 |
| Spring `@Autowired` 注入的流程 | RUNTIME 注解 → 反射扫描字段 → 读取注解 → `field.set()` 注入 |
