# 浏览器渲染

拿到服务器返回的 HTML/CSS/JS 后，浏览器如何把它们变成用户看到的页面。

---

## 一、整体流程

```
HTML 字节流
    ↓ 解析
DOM 树 + CSSOM 树
    ↓ 合并
渲染树（Render Tree）
    ↓
布局（Layout）— 计算每个节点的位置和尺寸
    ↓
绘制（Paint）— 将节点绘制成像素
    ↓
合成（Composite）— 多层合并，输出到屏幕
```

---

## 二、构建 DOM 树

浏览器收到 HTML 字节流后，经过以下步骤转为 DOM 树：

```
字节流 → 字符（UTF-8 解码）→ Token（词法分析）→ Node → DOM 树
```

解析过程是**增量的**：边下载边解析，不等 HTML 全部下载完。

### 遇到 script 标签会暂停解析

JS 可以修改 DOM（如 `document.write`），所以浏览器遇到 `<script>` 时**必须暂停 HTML 解析**，等 JS 下载并执行完才继续。这就是为什么 script 标签通常放在 `</body>` 前，或加 `defer`/`async`。

| 属性 | 下载时机 | 执行时机 | 是否阻塞解析 |
|---|---|---|---|
| 无属性 | 立即下载 | 立即执行 | 阻塞 |
| `defer` | 并行下载 | DOM 解析完后按顺序执行 | 不阻塞 |
| `async` | 并行下载 | 下载完立即执行（顺序不保证） | 下载不阻塞，执行阻塞 |

---

## 三、构建 CSSOM 树

CSS 字节流同样经过 `字节 → 字符 → Token → Rule → CSSOM 树` 过程。

**CSSOM 构建会阻塞 JS 执行**：浏览器不知道 JS 会不会读取样式（`getComputedStyle`），所以执行 JS 前必须等 CSSOM 构建完。

因此：CSS 放 `<head>`（尽早下载），JS 放底部或用 `defer`（避免阻塞）。

---

## 四、渲染树（Render Tree）

DOM 树 + CSSOM 树 → 渲染树。

渲染树只包含**可见节点**：
- `display: none` 的节点不在渲染树里（`visibility: hidden` 在，但不绘制内容）
- `<head>`、`<script>` 等非可见标签不在渲染树里

---

## 五、布局（Layout / Reflow）

遍历渲染树，计算每个节点在屏幕上的**精确位置和尺寸**（px）。

触发 Reflow（重排）的操作代价很高，因为需要重新计算布局：
- 修改元素尺寸（width、height、padding、margin）
- 插入/删除 DOM 节点
- 读取布局属性（`offsetWidth`、`getBoundingClientRect`）会强制触发同步 Reflow

---

## 六、绘制（Paint / Repaint）

把渲染树的每个节点转换成屏幕上的实际像素，按层（Layer）分别绘制。

触发 Repaint（重绘）但不触发 Reflow 的操作：修改颜色、背景、阴影等不影响布局的样式。

**Reflow 必然触发 Repaint，Repaint 不一定触发 Reflow。**

---

## 七、合成（Composite）

现代浏览器把页面分为多个**图层（Layer）**，各自绘制后由 GPU 合成输出。

只触发合成（不触发 Layout 和 Paint）的操作性能最好：
- `transform`（位移、旋转、缩放）
- `opacity`

这就是为什么 CSS 动画用 `transform` 比直接改 `left`/`top` 性能好——后者触发 Reflow，前者只触发 Composite（由 GPU 处理）。

---

## 八、Vue SPA 的渲染方式

本项目是 Vue 3 单页应用（SPA），渲染方式与传统多页应用不同：

```
浏览器请求 https://your-domain.com/
    ↓
Nginx 返回 dist/index.html（只有一个空壳 <div id="app">）
    ↓
浏览器下载并执行 dist/assets/index-xxx.js（Vue 打包产物）
    ↓
Vue 运行时启动，接管 <div id="app">
    ↓
Vue Router 根据当前 URL 决定渲染哪个组件
    ↓
组件挂载，发起 API 请求（/api/...）
    ↓
拿到数据后更新响应式状态，Vue 重新渲染 DOM
    ↓
用户看到完整页面
```

### SPA 与传统 MPA 的区别

| | 传统多页应用（MPA） | Vue SPA |
|---|---|---|
| 每次跳转页面 | 服务器返回新的完整 HTML | 前端 JS 更新 DOM，不刷新页面 |
| 首屏速度 | 快（服务器直接返回完整内容） | 相对慢（需等 JS 下载执行） |
| 后续交互 | 每次都要请求新页面 | 只请求数据，体验流畅 |
| SEO | 友好（HTML 内容完整） | 不友好（爬虫看到的是空壳） |

### 虚拟 DOM 与 Diff

Vue 不直接操作真实 DOM（代价高），而是维护一棵**虚拟 DOM 树**（JS 对象），状态变化时：

```
旧虚拟 DOM 树
    ↓ Diff 算法（对比新旧树的差异）
新虚拟 DOM 树
    ↓ 只把差异部分同步到真实 DOM（最小化 DOM 操作）
真实 DOM 更新 → 浏览器 Repaint/Reflow
```

## 九、完整请求链路（首次访问本项目）

```
输入 https://your-domain.com/merchant/123

① DNS 解析：your-domain.com → 服务器 IP（nginx.md）
② TCP 三次握手：建立连接（tomcat.md）
③ TLS 握手：协商加密，验证证书（nginx.md）
④ HTTPS 请求到达 Nginx
⑤ Nginx 匹配 location /：返回 dist/index.html（静态文件）
⑥ 浏览器解析 HTML，下载 JS/CSS
⑦ Vue 启动，Router 解析 /merchant/123，渲染 MerchantDetailView
⑧ 组件发起 GET /api/merchant/123
⑨ Nginx 匹配 location /api/：proxy_pass → Gateway:80
⑩ Gateway 路由到 mhp-account:8081（网关GateWay.md）
⑪ MerchantServiceImpl.getDetail()：查 Redis 缓存（redis.md）
⑫ 缓存未命中 → 查 MySQL → 写回缓存（mysql.md）
⑬ 返回 MerchantVO JSON → 逐层返回 → Nginx → 浏览器
⑭ Vue 拿到数据，更新响应式状态，渲染完整页面
```
