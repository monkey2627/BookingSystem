## 基础框架设计说明

### 为什么需要这套基础框架

**`Result<T>`（统一响应包装）**
不用它的话，每个接口返回格式各异，前端无法写统一的响应拦截器。有了它，所有接口都是 `{"code":200,"message":"成功","data":{...}}`，前端只需一处判断 code 即可。

**`ResultCode`（错误码枚举）**
将所有业务错误集中管理，避免魔法数字散落在各处。code 分段设计：2xx 通用、1xxxx 档期、2xxxx 预约、3xxxx 用户，方便排查问题。

**`BusinessException`（业务异常）**
Service 层遇到业务错误时直接 `throw new BusinessException(ResultCode.SCHEDULE_FULL)`，不需要层层传递返回值，代码更简洁。由 `GlobalExceptionHandler` 统一捕获转为 `Result` 返回给前端。

**`GlobalExceptionHandler`（全局异常处理）**
拦截所有未处理异常，保证接口永远不会把堆栈信息暴露给前端。同时处理 `@Valid` 参数校验失败，自动提取第一个字段的错误信息返回。

### 文件位置

```
common/
├── Result.java
├── ResultCode.java
└── exception/
    ├── BusinessException.java
    └── GlobalExceptionHandler.java
```

### Controller 使用示例

```java
return Result.ok(merchantService.getById(id));   // 有数据
return Result.ok();                               // 无数据
throw new BusinessException(ResultCode.SCHEDULE_FULL);  // Service 层抛，Controller 无需处理
```

## 生产部署

服务器路径：`/home/cosplay/{docker-compose.yml, nginx/, backend/app.jar, frontend/dist/}`

**生产与本地 docker-compose 的区别：**
- 中间件用 `expose`（不对外暴露端口）
- RabbitMQ 管理台只绑 `127.0.0.1:15672`
- 应用加 `--spring.profiles.active=prod` 和 JVM 参数 `-Xms256m -Xmx512m`

```nginx
location / {
    root /home/cosplay/frontend/dist;
    try_files $uri $uri/ /index.html;
}
location /api/ {
    proxy_pass http://localhost:8081;
}
location /ws/ {
    proxy_pass http://localhost:8081;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

SSL：`sudo certbot --nginx -d your-domain.com`。上线前需完成 ICP 备案（约 20 个工作日）。
